# 퍼즐 맵 스튜디오

[▶ 맵툴 실행하기](https://sungmin2ee.github.io/PuzzleMapStudio-Web/)

설치 없이 브라우저에서 격자 맵을 만들고, Unity·Unreal·개인 게임 프로젝트에서 읽을 JSON으로 내보내는 편집기입니다. **게임 규칙을 실행하는 도구는 아닙니다.** 중력·생성·승리 판정 등은 내보낸 키를 읽는 게임 코드에서 구현합니다.

## 지금까지 추가한 기능

| 분야 | 기능 |
|---|---|
| 타일 팔레트 | 이미지 등록, 아틀라스 자르기, 점유 크기 설정, ID·이미지 수정, 사용 중인 타일 삭제 방지 |
| 격자 편집 | 배치·지우기·90도 회전·실행 취소·판 초기화 |
| 영역 편집 | 드래그 선택, 여러 칸 배치·삭제, 속성 일괄 적용·제거, 같은 레벨·다른 레벨로 복사·붙여넣기 |
| 레벨 | 추가·복제·삭제·순서 변경, 선택적 이름, 고정 ID |
| 사용자 속성 | 레벨·칸·배치 타일 속성, 태그·텍스트·숫자·체크박스·선택 목록, 키 수정과 참조 갱신 |
| 시각화 | 속성별 강조, 값별 색 구분, 사용 중인 타일의 레벨 이동·배치 강조 |
| 검사 | 격자 밖·겹침·없는 타일 참조 검사, 프로젝트 공통·레벨 전용 개수 규칙 |
| 클리어 목표 | 사용자 정의 종류, 대상 없음·타일 선택·직접 입력, 수량 선택, 여러 목표와 완료 조건 |
| 저장·내보내기 | 브라우저 자동 저장, 이미지 포함 프로젝트 백업, 현재·전체 레벨 JSON |
| 데이터 유지 | 동일 이미지 데이터 공유, ID·속성 키 변경 시 기존 배치·복사 영역 등 관련 참조 갱신 |

## 처음 만드는 순서

1. 팔레트의 **＋**를 눌러 타일을 등록합니다. ID는 `ice_block`, 이름은 `Ice_Block`처럼 입력하고 이미지를 고릅니다.
2. 오른쪽 **맵 설정**에서 열·행을 입력하고 **설정 적용**을 누릅니다.
3. 팔레트에서 타일을 고르고 **배치** 상태에서 격자를 클릭합니다. 회전 버튼으로 방향을 바꾸고 **지우기**로 제거합니다.
4. 필요하면 **＋ 속성 추가**와 **클리어 목표 추가**로 데이터를 설정합니다.
5. **내보내기 전 검사**로 오류를 확인합니다.
6. **백업 저장**으로 편집용 파일을 보관하고, **현재 레벨 JSON** 또는 **전체 레벨 JSON**으로 게임용 데이터를 내보냅니다.

## 타일과 이미지

- 타일 ID는 게임이 읽는 식별자입니다. 다른 타일과 중복될 수 없습니다.
- 가로·세로 크기는 이미지 픽셀이 아니라 차지하는 칸 수입니다. 예: `2 × 1` 상자.
- **아틀라스에서 자르기**를 켜면 한 이미지의 일부를 사용할 수 있습니다. 영역 좌표와 크기는 원본 이미지의 픽셀 기준입니다.
- 팔레트 이미지를 수정하면 그 ID로 배치한 타일에도 반영됩니다.
- 등록한 이미지는 브라우저 저장소에 복사됩니다. 컴퓨터에서 원본 이미지 파일을 삭제해도 등록된 이미지는 유지됩니다.
- 동일한 이미지 데이터는 서로 다른 타일 ID에서 공유합니다. 타일 ID와 설정은 각각 유지됩니다.
- 사용 중인 타일은 삭제가 막힙니다. 안내된 레벨을 눌러 이동하고 배치된 칸을 찾을 수 있습니다. 타일 선택 방식의 클리어 목표에서 참조하는 경우도 삭제가 제한됩니다.

## 레벨 관리

- **＋ 레벨 추가**: 새 빈 레벨을 만듭니다.
- **레벨 복제**: 배치·회전·속성·목표 등을 복사한 새 레벨을 만듭니다.
- **↑ / ↓**: 목록 순서를 바꿉니다. 앞의 ‘레벨 1, 레벨 2’는 현재 순서입니다.
- **레벨 삭제**: 선택 레벨을 삭제합니다. 최소 한 레벨은 남겨야 합니다.
- 이름은 선택입니다. 비우면 게임용 JSON에서 `title`을 생략합니다.
- `levelId`는 고정 식별자입니다. 앞 레벨을 삭제해도 남은 ID를 다시 번호 매기지 않습니다. 플레이 순서는 전체 JSON의 `levels` 배열 순서로 읽으세요.

## 여러 칸과 복사·붙여넣기

1. **여러 칸 선택**을 켜고 드래그합니다. 새로 드래그하면 이전 선택을 바꿉니다.
2. **선택 칸에 배치**, **선택 타일 지우기**, **선택 칸 속성**, **선택 타일 속성**을 사용합니다.
3. **영역 복사**를 누릅니다.
4. 같은 레벨 또는 다른 레벨에서 **영역 붙여넣기**를 누르고, 복사 영역의 왼쪽 위가 놓일 칸을 클릭합니다.

배치·회전·칸 속성·배치 타일 속성이 함께 복사됩니다. 타일 ID나 속성 키를 바꾸면 복사해 둔 영역에도 반영됩니다. 복사 영역은 작업 중 임시 데이터이므로 새로고침 후에는 다시 복사하세요.

**판 초기화**는 현재 레벨의 배치 타일과 칸 속성을 지웁니다. 팔레트와 다른 레벨은 유지하며 실행 취소로 복구할 수 있습니다.

## 사용자 정의 속성

**＋ 속성 추가**에서 적용 대상, 키, 표시 이름, 값 형식을 정합니다.

| 적용 대상 | 의미 | 예시 |
|---|---|---|
| 레벨 | 맵 전체의 설정 | `move_limit = 30` |
| 칸 | 타일이 없어도 그 위치에 남는 설정 | `spawn` 생성 지점 |
| 배치 타일 | 그 위치에 놓인 타일 하나의 설정 | `hp = 2` |

**레벨 속성**에서 맵 전체 값을 입력합니다. **칸·타일 속성**을 켜고 칸을 누르면 그 칸과 배치 타일에 값을 부여할 수 있습니다. 한 곳에 여러 속성을 함께 넣을 수 있습니다. **속성 관리**에서는 기존 속성의 키·이름·형식을 수정하거나 삭제합니다.

| 값 형식 | 게임용 JSON 예시 |
|---|---|
| 값 없음(태그) | `"spawn": true` — 제거하면 키 자체가 없어짐 |
| 텍스트 | `"gravity": "down"` |
| 숫자 | `"hp": 2` |
| 체크박스 | `"locked": true` 또는 `false` |
| 선택 목록 | `"team": "black"` |

표시 이름은 한글을 쓸 수 있습니다. **게임용 JSON으로 나가는 문자열과 키는 영문·숫자·밑줄·하이픈만 사용**합니다. 속성의 한글 표시 이름은 편집기·백업용입니다. `spawn`을 만들었다고 자동으로 블록이 생성되지는 않습니다. 게임에서 그 키를 처리해야 합니다.

격자의 **표시할 속성**을 고르면 해당 속성이 붙은 위치를 강조합니다. 값이 있는 속성은 값별 색으로 구분합니다.

## 클리어 목표

오른쪽 **현재 클리어 목표** 영역에서 완료 조건과 등록된 목표를 확인합니다. **클리어 목표 추가**를 누르면 목록이 열립니다.

### 목표 종류를 처음 만들 때

1. **종류 관리 → ＋ 새 종류 만들기**를 누릅니다.
2. 예시를 선택하거나 직접 이름과 키를 입력합니다.
3. 대상 방식을 선택합니다.
   - **대상 없음**: 점수 달성, 모든 칸 채우기처럼 별도의 대상이 필요 없는 조건.
   - **타일 선택**: 팔레트에 등록한 타일을 목표로 지정.
   - **직접 입력**: `black` 같은 게임에서 정한 식별자를 입력.
4. 수량이 필요하면 **수량 입력**, 성공 여부만 필요하면 **수량 없음**을 선택합니다.
5. 저장하고 이전 목록으로 돌아가 **＋ 목표 추가**를 누릅니다. 종류·대상·수량을 설정하고 미리보기 문장을 확인합니다.

| 예시 | 종류 키 | 대상 | 수량 |
|---|---|---|---|
| 얼음 10개 수집 | `collect` | 타일 선택: `ice_block` | 10 |
| 점수 1000 달성 | `score` | 없음 | 1000 |
| 모든 칸 채우기 | `board_full` | 없음 | 없음 |
| 검은 팀 승리 | `win_match` | 직접 입력: `black` | 없음 |

이 예시는 데이터 구성 방법입니다. `board_full`이나 `win_match` 등의 실제 판정은 게임에서 구현합니다. 오셀로처럼 보드가 차기 전에 대국이 종료될 수 있는 게임은 원하는 종료·승리 규칙에 맞는 종류를 정의하세요.

### 완료 조건

- **모두 달성**: 등록한 목표를 전부 만족해야 완료.
- **하나 이상 달성**: 등록한 목표 중 하나를 만족하면 완료.
- **목표 없음**: 등록한 목표는 백업에 보관하되 게임용 JSON에는 빈 목록을 내보냄.

목표와 종류는 각각 **수정** 버튼으로 편집할 수 있습니다. 종류 키 변경은 기존 레벨 목표에도 반영됩니다. 종류는 모든 레벨에서 공유하므로 종류 설정을 바꾸면 그 종류를 사용하는 목표에도 영향을 줍니다.

## 검사 규칙과 내보내기

**검사 규칙**에서 현재 레벨의 방식을 고릅니다. 기본은 **규칙 없음**입니다.

- **이 레벨 전용 규칙**: 선택 레벨에서만 검사.
- **프로젝트 공통 규칙**: 공통 규칙을 선택한 레벨에 적용.

예를 들어 칸 속성 `spawn`이 **최소 1개**, 타일 `king`이 **정확히 1개**라는 조건을 추가할 수 있습니다. 기존 규칙의 조건과 개수도 수정 가능합니다.

**내보내기 전 검사**는 격자 밖 배치, 겹침, 없는 타일 참조, 사용자 규칙 및 목표 데이터 등을 확인합니다. 문제의 레벨과 좌표가 표시되며 위치가 있는 오류를 누르면 해당 위치로 이동합니다. 검사 규칙은 편집·백업용이며 게임용 JSON에는 포함되지 않습니다. 게임 플레이 중의 클리어 목표와는 별개입니다.

## 저장과 백업의 차이

| 방식 | 용도 | 이미지 |
|---|---|---|
| 자동 저장 | 같은 브라우저·같은 사이트에서 이어서 편집 | 포함 |
| 백업 저장 (`.puzzlemap`) | 다른 PC로 이동, 복구, 재편집 | 포함 |
| 현재 레벨 JSON | 선택한 레벨을 게임에 전달 | 제외 |
| 전체 레벨 JSON | 모든 레벨을 배열로 게임에 전달 | 제외 |

자동 저장은 계정 동기화가 아닙니다. 브라우저 데이터 삭제, 다른 브라우저·PC 사용 시 작업이 보이지 않을 수 있습니다. 중요한 작업은 **백업 저장**으로 파일을 보관하세요. 복원은 **프로젝트 열기**에서 `.puzzlemap`을 선택합니다. 게임용 JSON은 편집용 백업 대신 사용할 수 없습니다.

## 게임에서 JSON 읽기

현재 레벨 JSON 예시:

```json
{
  "schemaVersion": 1,
  "levelId": 3,
  "title": "Ice_Stage",
  "cols": 5,
  "rows": 5,
  "origin": "top-left",
  "objectives": {
    "mode": "all",
    "items": [{"type": "collect", "target": "ice_block", "count": 10}]
  },
  "properties": {"move_limit": 30},
  "cellProperties": [{"col": 0, "row": 0, "properties": {"spawn": true}}],
  "tileDefinitions": [{"id": "ice_block", "title": "Ice_Block", "width": 1, "height": 1}],
  "tiles": [{"tileId": "ice_block", "col": 0, "row": 1, "rotation": 0, "width": 1, "height": 1, "properties": {"hp": 2}}]
}
```

전체 레벨 JSON은 `{"schemaVersion": 1, "levels": [...]}` 구조입니다.

1. `levels` 배열 순서로 스테이지 목록을 구성하고, `levelId`로 저장 데이터 등을 연결합니다.
2. `tileId`를 Unity 프리팹, Unreal Actor 또는 게임의 오브젝트에 매핑합니다. 같은 맵 데이터로 2D·3D 오브젝트를 사용할 수 있습니다.
3. 좌표는 왼쪽 위가 `(0, 0)`이며 열은 오른쪽, 행은 아래로 증가합니다. 게임의 좌표계와 칸 크기에 맞춰 변환합니다.
4. `rotation`은 시계 방향 각도입니다. 타일 정의의 크기는 회전 전, 배치의 `width`·`height`는 회전 후 점유 크기입니다.
5. `properties`, `cellProperties`, 배치의 `properties`와 `objectives`를 읽어 게임 로직에 연결합니다.

이미지·프리팹·실제 중력이나 승리 판정 코드는 JSON에 포함되지 않습니다. 맵툴에서 새로운 키를 추가해도 게임 코드가 그 의미를 자동으로 이해하지는 않습니다.
